# Phase 6: default-on capture and native views

Capture flags are nullable choices. `Captain.UsageCaptureActive`, `UsageCaptureSettings.EffectiveEnabled` and `EffectiveAllowPtyFallback` resolve unset values to true. Disabled mode always wins. Clients preserve null when editing other fields.

Migration 113 makes `captains.usage_capture_enabled` nullable on SQLite, PostgreSQL, MySQL and SQL Server and resets pre-upgrade values to NULL once. SQLite replaces only that column because it cannot alter its nullability. No captain identity, mission state or other column is removed. Settings load resets Enabled and AllowPtyFallback to null once when DefaultsRevision is absent or below 2, persists revision 2, and respects subsequent explicit opt-outs.

**Upgrade notice:** explicit capture opt-outs saved by the earlier v1.2.0 build are reset too. Operators who want capture or PTY fallback off must opt out again after upgrading. No token accounting setting changes.

Raw snapshot retention now runs on the retention cadence in retry-safe transactions of at most 500 observations, at most 200 batches per pass. Each batch removes member links with its observations. The default cutoff is seven days, exclusive; latest-state windows and their original observation timestamps survive pruning. Hourly rollups remain phase 8 work.

Claude OAuth capture reads the existing host-local credential and provider account/organization UUIDs, HMACs identity on the host and calls only GET /api/oauth/usage. Unknown experimental/billing/application response properties are ignored by a typed allowlist. Opus and Sonnet windows retain their provider-reported family scope; exact-model routing does not guess family aliases for fully qualified model names. Gemini reads the existing Google-login profile and access token from the native keychain, vendor-encrypted fallback or legacy file, then verifies the active identity through the CLI's read-only OAuth userinfo operation; it resolves an existing Code Assist project using loadCodeAssist when necessary and calls retrieveUserQuota. The resolved project participates in the host-local credential-profile HMAC so distinct project budgets remain distinct series. Neither probe refreshes credentials, onboards a project or invokes a model. Sources are undocumented provider interfaces. Missing authentication, missing identity, throttling, malformed payloads and unavailable endpoints remain distinct outcomes. Relative quota percentages do not become token counts.

The PTY fallback starts an isolated 120x40 English terminal, bounds output and lifetime, discards OSC content, and sends only /usage or /stats after recognizing idle input. Trust, login and setup screens end the attempt without an answer. Gemini session-only stats are Unsupported, never inferred quota. All exits terminate the helper process tree. The global PTY flag can prohibit this fallback.

POST /api/v1/usage/{latest,snapshots,missions}/enumerate shares validation and authorization with GET. The series endpoint remains a bounded summary (20 series, 576 points each) and is explicitly allowlisted by the collection-surface gate. Usage response collections declare their bounds. The API baseline records the new routes and nullable settings choices.

TUI/mobile mappings are in DASHBOARD_PARITY.md. The release does not claim a live Gemini success without a signed-in Gemini account, nor a successful PTY quota scrape when the installed CLI stops at setup. PROBE_INTERFACES.md records host evidence and limitations.

Test-server fixtures explicitly opt out of background capture; default-on API tests opt back in. Long-lived test health loops therefore cannot borrow a developer's live provider credentials. Live provider checks remain deliberate host evidence, separate from CI.

Idle captain follow-up: migration 114 adds nullable `Captain.UsageCaptureHarborId` on all four providers. The saved credential Harbor takes precedence over the current dock, survives idle state and restart, and does not affect mission placement. Set it under Usage > Capture settings > Credential Harbor and save, then Capture now. REST/MCP capture with an explicit HarborId also saves the choice with a tenant-scoped column update that preserves concurrent mission and dock state. Omitted fields preserve the saved choice; explicit null clears it to automatic resolution. An automatic dockless captain in a split deployment returns 409 HostUnresolved with selection guidance; a selected but disconnected Harbor returns 503 HostUnavailable, and a disabled Harbor returns 409 HostDisabled. No fallback uses the Admiral's credentials. The first manual read can bypass startup jitter, but not a cooldown after an observation or a persisted lease.

Idle-capture validation: 160 usage, scheduler, host-execution, API and captain-form checks pass. The public surface/authorization/bounds checks also pass. Persistence and migration checks pass 21/21 on each of SQLite, PostgreSQL, MySQL and SQL Server. Dashboard build and 1,578 tests pass; mobile typechecking and 1,381 tests pass, with the updated form and capture cases rechecked 22/22. Both .NET targets build without warnings or errors.
