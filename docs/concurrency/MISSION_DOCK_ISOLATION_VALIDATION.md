# Mission worktree isolation validation

Mission instructions, REST/MCP live diffs and completion now resolve the mission’s recorded DockId through one shared resolver. They never borrow a captain’s singular dock or choose an active worktree just because its branch matches. The resolver checks the mission tenant/vessel and retains caller-specific dock access for public reads. Completion retains its internal access to the explicitly linked dock; it does not require the mission creator to own a vessel’s dock. Saved diff files/database snapshots and saved instructions retain their existing fallback behavior. No schema, request fields or response fields change.

Missing/deleted/inconsistent dock references yield the existing REST 404 or MCP Unavailable response when no saved artifact exists. Existing remote-host handling and its 503/Unavailable errors remain. All five Dashboard mission-diff entry points now forward errors to the shared DiffViewer, which uses the existing global ErrorState banner. Failed reads no longer masquerade as “No modified files”; successful empty diffs retain that empty state. Error text is rendered as React text, separately from parsed diff content, with file navigation/statistics/copy hidden for failures.

## Manual validation

Run independent missions on one multi-slot captain. Open each mission’s Diff and Instructions: they must show its own work. Complete one and confirm its sibling remains assigned with its own dock. For a historical mission with a missing dock, saved artifacts should still display. With neither a recorded dock nor a saved artifact, show an unavailable explanation even if another active dock shares its captain or branch; do not report an empty successful diff. The same refusal must hold for MCP get_mission_diff.
